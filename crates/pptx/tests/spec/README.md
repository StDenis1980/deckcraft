# Spec corpus

Decks written by hand, part by part, from ECMA-376 Part 1 (PresentationML §19, DrawingML §20–21)
and laid out the way PowerPoint packages a presentation (one master, its layouts, a theme, numbered
slides). Unlike the `corpus_*` tests, nothing here comes out of DeckCraft's own writer, so the
reader is tested against XML it did not produce. No file here was made by PowerPoint or any other
product; all text, names and colours are our own.

- `common/` holds the parts every deck shares: the theme, the slide master and two layouts.
- `decks/<name>/` holds a deck's own parts: its slides (`slideN.xml`, with `slideN.xml.rels` when
  a slide links to more than its layout) and anything else it needs (notes, media).
- `tests/it/spec_corpus.rs` packages each deck (content types and relationships are generated),
  imports it, checks what the deck is meant to show, saves it and imports the result again.

Binary media (pictures, a video) are generated by the test, not stored.
